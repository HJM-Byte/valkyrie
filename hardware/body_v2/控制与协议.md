# v2 控制与协议

三个新功能不是三个孤立的按键：电源键在硬件层，语音/主动消息键在身体固件层，最终都落到 PC 的同一份运行时状态。

## 1. 状态定义

PC 持久化文件：`robot/data/body_controls.json`

```json
{
  "version": 1,
  "voice_enabled": true,
  "proactive_enabled": true,
  "updated_at": 1762000000.0,
  "source": "body"
}
```

规则：

- 两个开关默认 `true`；文件不存在按默认值。
- 写入用 `临时文件 + os.replace()` 原子替换；不要直接覆盖。
- `source` 记录最后写入方：`body` / `phone` / `pc`。
- 最后一次写入生效；PC 通过 `ctrl` 把结果广播给身体，通过 `/api/state` 给手机。
- 开关只影响**新行为**，不改记忆、不改人格、不改 `Chat.turn()` 的调用时机。

## 2. 语音开关

### 2.1 语义

`voice_enabled = false` 表示**她的声音输出关**，不是麦克风关，也不是对话关。

- PC：`/api/tts` 直接返回 `409 VOICE_OFF`，不合成、不缓存新音频。
- 身体：TCA9534 P6 拉高，经 Q3 把 MAX98357A `SD` 拉低；正在播的音频立即停。P6 低时 Q3 释放，SD 由模块上拉恢复默认 (L+R)/2。
- 手机：显示“语音关”；文字回复仍显示；不自动补播关闭期间的消息。
- 麦克风、STT、Chat、记忆全部照常；她仍然能听见、能回文字。

### 2.2 与 MUTE 的区别

| | VOICE | MUTE |
|---|---|---|
| 层级 | 全局输出开关 | 本地临时静音 |
| 持久化 | 是 | 否（重启恢复） |
| 影响手机 TTS | 是 | 否 |
| 功放 SD | 直接关断 | 由音量/播放控制 |
| 用途 | 不想让她出声 | 临时压一下 |

MUTE 保留 v1 行为：短按切换本地静音；VOICE 是更高一层的总开关。

## 3. 主动消息开关

### 3.1 语义

`proactive_enabled = false`：

- `proactive.can_send()` 返回 `{"ok": false, "reason": "主动消息开关关着"}`。
- `proactive_seed()` 不被生成循环调用；不生成新消息。
- `proactive.db` 里 `status='new'` 的旧消息**保留**，不删除；重新打开后按原逻辑取走。
- 手机 `/api/proactive` 在关闭时可以返回空列表/204；不要偷偷投递旧消息。
- 保留原有边界：睡着不发、精力 <0.25 不发、48 小时内不重复原问题、主动消息不写记忆。

### 3.2 与 `PROACTIVE_ENABLED` 的关系

`config.PROACTIVE_ENABLED` 是启动级总开关（环境变量/命令行）；`body_controls.proactive_enabled` 是运行时开关。两者是 **AND**：

```
can_send = PROACTIVE_ENABLED and body_controls.proactive_enabled
```

启动级关闭时，运行时开关不能强行打开；运行时关闭时，启动级开着也不发。

## 4. 电源键

### 4.1 硬件层

- S1 面板键直接并联在 IP5306 `KEY` 与 GND。
- GPIO48 经 1k 驱动 NPN，集电极接 `KEY`：心跳 100ms，软关机 2.5s。
- BSS138 把 `KEY` 反相到 GPIO1；`KEY` 先串 R5 100k 到栅极，栅源 R6 100k 下拉；不装 5.1V 稳压管。

### 4.2 固件时序

```text
上电/复位
  → 初始化 GPIO1/GPIO48
  → 启动 12s 心跳定时器
  → 每 12s：GPIO48 高 100ms；期间忽略 GPIO1 的高电平
  → 读 GPIO1：
      按下沿记录 t0
      松开沿计算 dt
      dt < 0.3s           → 忽略（抖动/点按）
      0.3s ≤ dt ≤ 1.5s    → 软关机流程
      dt > 2.0s           → 不做事（IP5306 已经硬断）
软关机流程：
  发 {"type":"event","event":"power","action":"shutdown"}
  等 PC ack 最多 300ms（PC 离线也继续）
  保存 NVS（音量/开关状态）
  GPIO48 高 2.5s
  IP5306 长按断电
```

**注意**：0.3–1.5s 的窗口里，IP5306 只把按键当短按，不会关；固件在松开后主动模拟长按。按住超过 2s 时 IP5306 会先硬断，固件来不及软关——这是有意的逃生通道。

### 4.3 不依赖 PC

电源键必须在 PC 离线时也能用。软关机流程里 PC ack 只是“通知”，不是前置条件；等不到就继续断电。身体没有关键文件系统，断电风险低；NVS 只存配置。

## 5. WebSocket 协议

在 v1 的 `hello` / `state` / `face` / `snap` / `ctrl` / `ping` 上增加：

### 5.1 握手

```json
// body -> PC
{
  "type": "hello",
  "fw": "2.0",
  "mac": "AA:BB:CC:DD:EE:FF",
  "mic": 16000,
  "cam": "ov2640",
  "caps": ["power_key", "proactive_key", "voice_key", "ina226"],
  "token": "..."
}
```

PC 回：

```json
{
  "type": "welcome",
  "sample_rate": 16000,
  "frame_ms": 30,
  "chunk_ms": 30,
  "face_hz": 5,
  "controls": {"voice_enabled": true, "proactive_enabled": true}
}
```

### 5.2 事件

```json
// body -> PC
{"type":"event","event":"proactive","enabled":false,"ts":1762000000.0}
{"type":"event","event":"voice","enabled":true,"ts":1762000000.0}
{"type":"event","event":"power","action":"shutdown","ts":1762000000.0}
```

PC 处理：

- `proactive` → 写 `body_controls`，回 `ctrl`。
- `voice` → 写 `body_controls`，回 `ctrl`；如果关闭，停止当前 TTS/播放。
- `power` → 记日志，回 `ack`；不阻止身体断电。

### 5.3 状态同步

```json
// PC -> body
{"type":"ctrl","voice_enabled":true,"proactive_enabled":false,"amp_sd":true}

// body -> PC
{"type":"battery","mv":3920,"ma":-380,"pct":78,"alert":false}
```

`amp_sd` 是逻辑字段：`true` = 功放开。身体以 `voice_enabled` 为准；物理上 P6 高 = Q3 拉低 SD = 关，所以固件写 P6 时要取反。保留 `amp_sd` 方便调试。

### 5.4 断线与补发

- 身体 NVS 保存最近 16 条未确认事件（环形队列）。
- 重连 `hello` 后先发 `event`；PC 回 `ctrl` 后标记已确认。
- 事件去重：`event + ts`；PC 收到重复只处理一次。
- 电源事件不需要补发：断电后没发出去就算了，PC 不需要知道每一次关机。

## 6. PC API

### 6.1 `/api/state`

在现有返回里加：

```json
{
  "controls": {
    "voice_enabled": true,
    "proactive_enabled": false,
    "updated_at": 1762000000.0,
    "source": "body"
  }
}
```

### 6.2 `/api/control`

```http
POST /api/control
X-Valkyrie-Token: ...
Content-Type: application/json

{"voice_enabled": false}
```

返回：

```json
{"ok": true, "controls": {"voice_enabled": false, "proactive_enabled": true}}
```

规则：

- 两个字段都可选；只改传入的。
- 未知字段忽略；类型不对返回 400。
- 需要配对码；和现有 API 一样。
- 写盘成功才返回 ok；写盘失败返回 500，不改内存状态。

### 6.3 `/api/tts`

当 `voice_enabled=false`：

```json
{"ok": false, "error": "语音关着", "code": "VOICE_OFF"}
```

HTTP 409。不要合成、不要返回缓存音频；否则手机可能继续播。

### 6.4 `/api/proactive`

当 `proactive_enabled=false`：

- 不生成新消息。
- 返回空列表或 204；已有队列保留在 DB。
- 不要为了“关闭”清空旧消息。

## 7. 固件伪代码

```c
// power_task
static void power_task(void *arg) {
    bool last = false;
    int64_t press_at = 0;
    int64_t last_beat = 0;
    while (1) {
        int64_t now = esp_timer_get_time() / 1000;
        if (now - last_beat >= 12000) {
            gpio_set_level(PIN_IP5306_KEY, 1);
            vTaskDelay(pdMS_TO_TICKS(100));
            gpio_set_level(PIN_IP5306_KEY, 0);
            last_beat = now;
            // 心跳窗口内忽略 PWR_KEY_SENSE；这 100ms 不是用户按键
            last = false;
            vTaskDelay(pdMS_TO_TICKS(150));
            continue;
        }
        bool pressed = gpio_get_level(PIN_PWR_KEY_SENSE);
        if (pressed && !last) press_at = now;
        if (!pressed && last) {
            int64_t dt = now - press_at;
            if (dt >= 300 && dt <= 1500) {
                protocol_send_power_event();
                vTaskDelay(pdMS_TO_TICKS(300));
                nvs_save();
                gpio_set_level(PIN_IP5306_KEY, 1);
                vTaskDelay(pdMS_TO_TICKS(2500));
                gpio_set_level(PIN_IP5306_KEY, 0);
            }
        }
        last = pressed;
        vTaskDelay(pdMS_TO_TICKS(20));
    }
}
```

生产代码要把心跳和按键窗口做成状态机，不要在 `vTaskDelay` 里阻塞其他任务；这里只表达时序。

```c
// buttons_task：TCA9534 轮询，P0/P1 低有效，25ms 消抖
uint8_t p0 = tca_read_pin(0);
uint8_t p1 = tca_read_pin(1);
if (p0 == 0 && last_p0 == 1 && debounce_ok(0)) toggle(PROACTIVE);
if (p1 == 0 && last_p1 == 1 && debounce_ok(1)) toggle(VOICE);
last_p0 = p0;
last_p1 = p1;
```

## 8. 手机 UI 同步

- 设置页/对话页显示两个开关：语音、主动消息。
- 状态来自 `/api/state.controls`；切换调用 `/api/control`。
- 开关状态变化时，身体 LED 跟着变；手机和身体不要各存一份。
- 语音关时，对话页的播放按钮置灰；文字仍显示。
- 主动消息关时，通知/轮询不显示新主动消息；旧消息不补推。

## 9. 测试用例

| 编号 | 场景 | 期望 |
|---|---|---|
| V1 | 按 VOICE 关 | 功放静音；`/api/tts` 409；手机显示关；重启后仍关 |
| V2 | 按 VOICE 开 | 功放恢复；新回复有声；不补播旧消息 |
| V3 | 手机切 VOICE 关 | 身体 LED 灭；功放 SD 低；PC 持久化 |
| V4 | 按 PROACTIVE 关 | 1 分钟内不生成新主动消息；旧队列保留 |
| P1 | 按 POWER 0.8s 松开 | 发 power 事件；2.5s 内断电；PC 仍在 |
| P2 | 按住 POWER 3s | IP5306 硬断；不依赖固件 |
| P3 | 心跳运行 2 分钟 | 不自动待机 |
| P4 | 断 PC 网线 | 电源键仍能软关；事件重连后补发 |
| C1 | 身体/手机同时改 | 最后写入生效；两边最终一致 |
| C2 | 重启服务 | 开关状态保持；默认开 |

## 10. 安全边界

- WebSocket/HTTP 只在局域网；不要映射到公网。
- 配对码沿用 `VALKYRIE_APP_TOKEN`；`/api/control` 必须鉴权。
- 开关不改记忆、不删消息、不改人格；只是行为门。
- 身体断电不关 PC；PC 断电不关身体（电池仍供电直到 IP5306 关）。
- 不要把 KEY 节点直接接 ESP32 GPIO；必须经 R5 100k 到 BSS138 栅极，栅源 R6 100k 下拉。
